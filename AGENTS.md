# Project guidance

- Keep this a static React/Vite catalog with local JSON content and local image files. Do not add a backend, database, authentication, or AI API calls unless explicitly requested.
- Preserve the light Playnite/Dune-inspired design and the selected game's subtle background tint with smooth transitions.
- UI text is Swedish. Keep it accessible and responsive, and honor reduced motion.
- Content lives in src/games.json; assets live in public/images. Real game images belong in public/images/games/<stable-game-id>/. Reusable SVG themes live in public/images/placeholders/; preserve their variants and archived covers. Define fallback paths centrally in src/constants/placeholderThemes.ts and use GameImage for fallback/error handling. See public/images/README.md.
- Imported player counts and weights follow the user-reviewed catalog export; interaction is subjective and tags are curated. Preserve edition/preliminary caveats, especially Parlay. Unknown facts are null; never substitute demo values. Descriptions can remain drafts independently of imported facts. Match source rows/titles explicitly in scripts/catalog-matches.json and preserve stable ids. Notes must never be imported. Run node --test tests/catalog.test.mjs for catalog or filter changes.
- Favorites use localStorage and are per browser only.
- Use strict TypeScript: React components in .tsx; hooks, utilities, constants and Vite configuration in .ts. Shared game types live in src/types/game.ts. Check imported JSON against Game without forced type assertions.
- Keep component styles in adjacent .module.css files using plain CSS, not Sass. Use src/App.module.css for shared layout; reserve src/styles.css for fonts, base element styles and reduced motion. Preserve CSS variable inheritance, selector specificity and responsive rule order; pass explicit class props across component boundaries when needed.
- ESLint uses flat config with recommended TypeScript and React Hooks rules. Keep Prettier responsible for formatting; avoid broad rule suppressions and document any necessary targeted exceptions. npm run lint fails on errors and warnings.
- Keep the verified tooling versions pinned: ESLint 10.14.0, @eslint/js 10.0.1, TypeScript 6.0.3, typescript-eslint 8.72.1 and eslint-plugin-react-hooks 7.1.1. Supported Node versions are ^22.13.0 || >=24.0.0; CI and Netlify use 22.23.4.
- The remaining minimatch advisory GHSA-g3hv-75wg-m249 affects development tooling. Its fix in minimatch 11.0.1 is outside the current dependency ranges. Do not use force, overrides or incompatible downgrades to silence audit findings; reassess when a compatible upstream fix is available.
- Run npm run format, npm run format:check, npm run lint and npm run build after code changes. npm run typecheck is available separately; the build already includes typechecking. Do not commit node_modules or dist.
- GitHub Actions CI runs npm ci, npm run format, npm run lint and npm run build on pull requests to main and pushes to all branches, using Node.js 22.23.4 and contents: read. Do not add publishing or deployment to this workflow.
